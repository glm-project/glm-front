# CLAUDE.md

`glmfront` is an Angular 21 single-page application generated by [Seed4J](https://github.com/seed4j/seed4j), authenticating users against **Keycloak** (OIDC, via `keycloak-js`). It follows a **hexagonal architecture with DDD bounded contexts**, enforced at test time by `arch-unit-ts`.

## Commands

```bash
npm run dev              # serve app + watch (http://localhost:9000)
npm run build             # production build (target/classes/static)

npm test                  # alias for watch:test (ng test --watch, Vitest via Angular's unit-test builder)
ng test --watch=false      # run the unit suite once
ng test --watch=false -- <pattern>   # run a subset (Vitest CLI args after `--`), e.g. -- oauth2-auth
npm run test:coverage      # unit tests with Istanbul coverage report (target/test-results)

npm run test:component     # Cypress component tests (boots the dev server first)
npm run test:component:headless
npm run e2e                 # Cypress e2e tests, interactive (expects app already running on :9000)
npm run e2e:headless        # same, headless — still expects the app already on :9000
npm run test:e2e:headless   # e2e headless, boots the dev server itself — this is what CI runs

npm run lint                # eslint .
npm run prettier:check
npm run prettier:format
npx tsc --noEmit           # type-check without emitting
```

## Traps that cost

- Run unit tests through `ng test`, never bare `npx vitest run`: the `@angular/build:unit-test` builder (`angular.json`) injects the zoneless TestBed environment and the JIT compiler setup, and without it specs fail on misleading errors (`TestBed.initTestEnvironment()`, JIT compiler not available).
- Coverage is 100 % per file (`vitest.config.ts`, `coverage.thresholds`): one untested branch is a build failure, not a metric. Write the test alongside the code.
- Add `package-info.ts` before any new bounded context — otherwise `arch-unit-ts` silently checks nothing and the architecture drifts under a green build.
- Never edit `src/test/webapp/unit/HexagonalArchTest.spec.ts` to make a build pass: a failure means the code deviates, so fix the code.
- Keep the `# seed4j-needle-*` markers (`app.route.ts`, `main.ts`, `README.md`) when editing those files by hand — Seed4J module generators insert there.
- `httpAuthInterceptor` already attaches `Authorization: Bearer <token>` to every outgoing request (wired in `main.ts`): never re-attach it in an adapter.
- The `@/*` path alias resolves to `src/main/webapp/*`.

## Verification before claiming done

Nothing is "green", "validated" or "done" until it has run with exit code 0. If the environment blocks a run (network, proxy, certificates), say so — _"code written but NOT VERIFIED because of X"_ — and never simulate a success.

The commands CI runs, in order (`.github/workflows/github-actions.yml`):

```bash
npm run lint
npm run prettier:check
npx tsc --noEmit
npm run test:coverage -- --watch=false
npm run test:component:headless
npm run test:e2e:headless
```

Every summary that touches code or dependencies states:

- **Compilation:** `🟢 OK` | `🟡 NOT RUN (say why)` | `🔴 KO`
- **Tests:** `🟢 RUN & OK` | `🟡 NOT RUN (say why)` | `🔴 RUN & KO`

## Where the rules are

- Before writing or changing a test → `documentation/testing.md`
- Before adding a bounded context, a port, an adapter, or touching auth wiring → `documentation/architecture.md`
- Before writing or refactoring component or service code → `documentation/code-style.md`
- Before branching, committing or opening an MR → `documentation/git-and-mr.md`
- Before proposing a structural choice (new dependency, new pattern, deviation from a convention) → `documentation/adr/README.md`
